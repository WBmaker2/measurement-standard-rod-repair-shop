# 측정 기준봉 정비소 초등학생 실사용 점검 및 개선 계획

**점검일:** 2026-07-18  
**대상:** 초등학교 1~2학년 학생  
**점검 환경:** 데스크톱 1280×720, 모바일 375×667, 미션 5개 전체 흐름  
**기준 버전:** v1.0.1

## 1. 실사용 점검 범위

- 안내 활동에서 일부러 틀린 답을 고른 뒤 다시 시도했습니다.
- `어림 → 고장 찾기 → 수리 → 다시 세기 → 값 확인 → 이유 고르기`를 실제 버튼으로 진행했습니다.
- 시작점, 틈, 겹침, 서로 다른 칸 크기, 복합 고장 미션 5개를 모두 완료했습니다.
- 복합 고장에서 두 수리를 차례로 적용하고 마지막 측정 정비 기록까지 확인했습니다.
- 데스크톱과 모바일의 첫 화면, 버튼 크기, 가로 넘침, 콘솔 오류를 확인했습니다.

## 2. 확인된 장점

- 점수와 시간 제한이 없어 학생이 틀린 선택을 부담 없이 다시 시도할 수 있습니다.
- 모든 학습 조작을 버튼으로 할 수 있고 버튼 높이는 44px 이상입니다.
- 수리 전과 수리 뒤 기준봉을 같은 위치에서 비교할 수 있습니다.
- 틈, 겹침, 서로 다른 칸 크기를 색뿐 아니라 위치·무늬·글자로 함께 표시합니다.
- 모바일 375px에서 가로 스크롤이 생기지 않았고, 미션 5개를 끝까지 완료할 수 있었습니다.
- 전체 실사용 중 브라우저 경고와 오류가 발생하지 않았습니다.

## 3. 발견한 문제와 개선 결정

### P0. 작은 화면에서 지금 누를 버튼이 너무 늦게 보임

- 관찰: 모바일에서는 헤더의 보조 메뉴와 큰 작업대가 먼저 나오고, 현재 단계 설명과 선택 버튼은 첫 화면 아래로 밀립니다.
- 학생 영향: 그림을 본 뒤 무엇을 해야 하는지 바로 알기 어렵고, 버튼을 찾으려고 긴 화면을 내려야 합니다.
- 개선: 학습 중 모바일 화면은 `현재 할 일 → 선택 버튼 → 작업대` 순서로 배치합니다. 작업대에도 `고치기 전` 또는 `고친 뒤` 상태표를 붙입니다.
- 완료 기준: 375×667에서 현재 단계 제목과 첫 선택 버튼이 작업대보다 먼저 보입니다.

### P0. 계획은 다섯 단계인데 화면은 여섯 단계임

- 관찰: `다시 세기`에서 맞는 칸 수를 고른 뒤 `바른 값 확인하기`를 한 번 더 눌러야 합니다.
- 학생 영향: 이미 확인한 답을 다시 누르게 되어 활동 흐름이 끊기고 단계 수가 길어집니다.
- 개선: 맞는 칸 수를 고르면 바로 바른 길이를 알려 주고 `이유 고르기`로 이동합니다.
- 완료 기준: 화면 단계는 `어림 → 고장 찾기 → 고치기 → 다시 세기 → 이유`의 다섯 단계만 표시합니다.

### P1. 상태 알림과 지금 할 일이 서로 섞임

- 관찰: 첫 미션 시작 때 상태 상자에는 이전 안내 활동 완료 문장이 남고, 현재 행동은 다른 문단에 있습니다.
- 학생 영향: 어느 문장을 따라야 하는지 한 번 더 판단해야 합니다.
- 개선: 단계 안내에 `지금 할 일` 꼬리표를 붙이고, 상태 상자는 `방금 한 일`로 구분합니다. 새 미션 시작 알림도 현재 단계와 같은 말로 맞춥니다.
- 완료 기준: 현재 행동과 이전 결과가 시각적·문장으로 분리됩니다.

### P1. 일부 말이 저학년에게 어렵거나 딱딱함

| 기존 표현 | 개선 표현 | 이유 |
|---|---|---|
| 기준봉 | 화면 속 자 | 학생이 익숙한 낱말을 먼저 사용 |
| 모형 cm | 화면 속 cm | 버튼에서 짧게 읽고, 실제 cm가 아니라는 설명은 유지 |
| 0이 어긋남 | 시작이 0과 달라요 | 한자어와 명사형 표현 줄이기 |
| 정비 전 표시 | 고치기 전 숫자 | 학생 행동과 연결 |
| 바른 측정 | 고친 뒤 길이 | 결과를 구체적으로 설명 |
| 믿기 어려움 | 길이를 정할 수 없어요 | 무엇을 믿기 어려운지 분명히 표현 |
| 종합 점검 | 두 고장 함께 찾기 | 해야 할 일을 바로 드러냄 |

- 수학 안전장치: 첫 화면과 작업대에는 `화면 속 칸은 실제 1cm 크기가 아니에요`를 계속 표시합니다.

### P1. 오답 안내가 넓고 추상적임

- 관찰: 고장을 잘못 고르면 `0, 칸의 크기, 틈과 겹침을 차례로 봐요`처럼 여러 개념을 한꺼번에 제시합니다.
- 학생 영향: 어디부터 다시 볼지 알기 어렵습니다.
- 개선: `괜찮아요`로 다시 시도를 허용하고, 미션마다 한 가지 시각 단서를 짧게 제공합니다.
- 예시: `물체의 왼쪽 끝과 자의 0이 만났는지 봐요.`
- 완료 기준: 모든 오답 안내는 두 문장 이내이고 다음 관찰 행동 하나만 제시합니다.

### P1. 마지막 정비 기록이 한 문장으로 너무 김

- 관찰: 미션 한 개의 어림, 고장, 수리, 전후 값, 이유가 가운데점으로 이어집니다.
- 학생 영향: 자신이 무엇을 했는지 핵심을 찾기 어렵습니다.
- 개선: 기록을 `내 어림 / 찾은 고장 / 고친 방법 / 고친 뒤 길이 / 알게 된 점` 다섯 줄로 나눕니다.
- 완료 기준: 모바일에서도 각 정보가 줄과 라벨로 구분되고, 긴 가운데점 문장이 남지 않습니다.

### P2. 학습과 교사용 메뉴의 우선순위가 같음

- 관찰: 모바일 첫 화면 상단에 `1m 카드`, `교사용 안내`, `업데이트 내역`이 모두 학생 시작 버튼보다 먼저 보입니다.
- 학생 영향: 시작 전에 보조 기능으로 시선이 분산됩니다.
- 개선: 학생용 `1m 살펴보기`와 `업데이트 내역`은 유지하고, 교사용 안내는 `선생님`으로 짧게 표시해 보조색을 사용합니다.
- 완료 기준: 학생 시작 버튼이 가장 강한 색과 크기를 유지하고, 보조 메뉴는 시각적으로 한 단계 낮습니다.

## 4. 구현 범위

- 여섯 단계를 다섯 단계로 단순화하고 불필요한 확인 버튼 제거
- 학생용 쉬운 문장과 미션별 한 문장 힌트 적용
- 모바일에서 행동 패널을 작업대보다 먼저 배치
- 작업대에 고치기 전·후 상태표 추가
- 측정 정비 기록을 다섯 줄 요약 카드로 변경
- 헤더 보조 메뉴 문장과 시각 위계 조정
- 2026-07-18 개선 내용을 앱의 `업데이트 내역`에 최신순으로 추가

## 5. 검증 기준

- 안내 활동과 미션 5개를 버튼만으로 끝까지 완료할 수 있습니다.
- 잘못 고른 뒤 상태가 막히지 않고 같은 단계에서 다시 고를 수 있습니다.
- 375×667에서 현재 할 일과 선택지가 작업대보다 먼저 보입니다.
- 320px 이상에서 가로 스크롤이 생기지 않습니다.
- 화면에 표시되는 단계가 다섯 개이고 `바른 값 확인하기` 버튼이 없습니다.
- 최종 기록이 다섯 개의 읽기 쉬운 카드로 표시됩니다.
- 화면 속 칸이 실제 1cm 크기가 아니라는 안내가 유지됩니다.
- 키보드 초점, 대화상자 초점 가두기, 움직임 줄이기 설정이 유지됩니다.
- 모든 코드 파일은 500줄 미만이고 테스트·빌드·린트가 통과합니다.

## 6. 구현 반영 기록

**반영일:** 2026-07-18  
**버전:** v1.1.0

- `어림 → 고장 찾기 → 고치기 → 다시 세기 → 이유`의 다섯 단계로 줄이고, 다시 세기 정답 뒤 바로 이유 고르기로 이동하게 했습니다.
- 각 미션의 짧은 힌트와 `지금 할 일`·`방금 한 일`을 분리해 다음 행동을 쉽게 찾을 수 있게 했습니다.
- 작은 화면에서 행동 패널과 선택지가 작업대보다 먼저 오도록 순서를 조정하고, 작업대에는 고치기 전·고친 뒤 상태를 표시했습니다.
- 마지막 기록을 미션별 다섯 줄 카드(`내 어림`, `찾은 고장`, `고친 방법`, `고친 뒤 길이`, `알게 된 점`)로 바꾸고, 학생용 메뉴 표현과 시각 위계를 다듬었습니다.
- 독립 리뷰에서 `화면 속 5cm`처럼 수와 단위를 자연스럽게 읽도록 통일하고, 마지막 미션의 첫 수리 뒤에는 이미 고친 곳이 아니라 남은 고장만 힌트로 안내하게 보완했습니다.
- 320px 화면에서 세로 스크롤바와 고정 최소 너비가 충돌해 생기던 가로 스크롤을 제거했습니다.

## 7. 최종 실사용 재검증

- 안내 활동에서 틀린 답을 고른 뒤 다시 시도할 수 있었습니다.
- 미션 5개를 처음부터 끝까지 다시 진행했고, `다시 세기` 뒤 불필요한 값 확인 없이 바로 다섯 번째 `이유` 단계로 이동했습니다.
- 마지막 복합 미션에서 겹침을 고친 뒤 `눈금 숫자가 0, 1, 2처럼 차례인지 봐요.`라는 남은 고장 힌트가 표시됐습니다.
- 375px에서 현재 할 일과 선택지가 작업대보다 먼저 표시됐고, 320px에서 `scrollWidth = clientWidth`로 가로 스크롤이 없었습니다.
- 모든 버튼과 링크의 보이는 조작 영역은 44px 이상이었고, 실사용 중 브라우저 경고와 오류는 없었습니다.
- 최종 기록 5개가 각각 `내 어림 / 찾은 고장 / 고친 방법 / 고친 뒤 길이 / 알게 된 점` 구조로 표시됐습니다.
- `npm run build`, `npm test` 8개, `npm run lint`가 모두 통과했습니다.
